You've now trained models, worked with LLMs, built apps, and deployed them. In this course those felt like separate skills. In industry, they are increasingly the same job.

## What's changing

A common pattern in job postings right now is traditional software roles that also expect data and AI experience. A backend or platform engineer is still expected to build APIs and run things in the cloud, and now they're also expected to process data, tune models, and deploy them.

The reason is that AI features are no longer a separate product built by a separate team. A "recommended for you" feed, a smart search box, or a support chatbot is just another feature of the app. The same engineer who builds the feature is often the one who handles the data behind it, picks and tunes the model, ships the interface, and runs it in production.

That means four things that used to be four job titles now sit on top of each other as layers of one stack:

- **Data** turning raw events into something a model can use
- **AI / Models** choosing, tuning, and evaluating a model
- **Full stack** building the API and the interface around it
- **Cloud** deploying, scaling, and monitoring it in production

## Why this matters for you

You don't need to be an expert in all four layers to be valuable. What helps is being comfortable moving between them, knowing enough to direct AI through each step, and being able to verify the result. That is exactly the way of working this course has been building toward, and it's what your final project asks you to put together.
