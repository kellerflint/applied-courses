This is the final submission for the whole project. Two things happen here: you ship the finished repo, and you book a demo meeting with your instructor during finals week.

## Final checklist

Before you submit, confirm all of this is true. Walk it with your partner, app open, going criterion by criterion.

- **All six user stories pass every acceptance criterion** against the real backend. Not "mostly." Every bullet.
- **Loading, error, and empty states** are handled and styled across the app.
- **The app looks deliberate.** Consistent palette, typography, and spacing on every page. Both Tailwind and CSS used.
- **Your own feature works** and you can both explain how it's built.
- **The app runs from a clean clone.** Clone the repo into a fresh folder, follow your own README, and start it. If it doesn't run, your README is wrong or you're depending on something that isn't committed.

> **With your partner:** Do the clean-clone test for real. Clone into a new folder, follow only what your README says, and start both the backend and the frontend. A common final-submission failure is "works on my machine" because a setup step lives only in someone's head.

## Your README

The repo's `README.md` must include:

- **Both partners' names.**
- **Setup and run instructions** for both the frontend and the backend repos. Assume the reader has the repos and no other knowledge.
- **Your color palette** (hex codes or Tailwind color names).
- **A short description of your own feature** and how to use it.
- Screenshots are optional but encouraged. They can make the repo look more professional and catch attention.

## Push to GitHub

Commit everything and push. Make sure nothing required is gitignored, and that both the frontend and backend code are in the repo.

## Submit on Canvas

**One partner** submits the frontend GitHub repo URL on Canvas. One submission per team.

## Book your demo

At the end of the quarter you'll demo the project to me and answer questions about your approach and implementation. The booking link is on **Canvas**.

- **Book one meeting per team**, and **both members attend**.
- Schedule it during **finals week**. Book early; the slots fill up.
- Expect it to take **10 to 15 minutes**. I'll ask you to walk through the app and explain how parts of it work, including your own feature, so be ready to talk about the code.
