## Keep It Small

The goal is to make one idea click, not to ship a product. One feature working live in front of the class teaches more than a big app that is half built and crashes mid-demo. Pick the smallest thing that clearly shows what your topic does, and get that working first. You can always add more once the core works.

## Learning Something New

You are going to be learning a tool you have not used before. Here is a path that works reliably:

1. **Find the official docs or quickstart.** Most libraries have a "getting started" page that takes you from zero to a working example. Start there, because official docs are usually correct and current where random tutorials are often out of date.
2. **Build the smallest possible working version.** Get the core feature running on its own before you wrap any styling or extra features around it. When something breaks, you want as little code as possible to search through.
3. **Then expand.** Once the core works, add the pieces that make it a clear, watchable demo.

> **With your partner:** Split the work. One of you can read docs and prototype the core feature while the other sets up the project and sketches what the demo will show. Agree on what "working" looks like before you start so you both know when you have hit it.

## Using AI to Learn

AI assistants are useful for picking up a new library quickly, and you are welcome to use them. The catch is the same as always in this course. You have to understand what you built well enough to explain it and answer questions during your presentation. If the AI writes something you do not follow, stop and figure out why it works before you move on, because "the AI did it" is not an answer you want to give in front of the class.

## Setup

For most of these topics you will spin up a fresh Vite and React project, the same way you have all quarter. A few topics, like a database or authentication, need a free account on an outside service. Create those accounts early so you are not stuck in a sign-up flow during your build time.

## Deploy (Optional)

If your demo is a front-end app, deploying it to GitHub Pages lets you present from the live URL and share it with classmates afterward. Some topics will not run on GitHub Pages as-is, including anything with a backend, a database, or secret API keys. Present those from your local dev server instead, which works just as well for a live demo.

> **With your partner:** Do a full dry run on the machine you will present from. Demos that worked an hour ago have a habit of breaking right before you show them, so you want to catch that now rather than in front of everyone.
